# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

MapUp full-stack assessment: a **geofencing + vehicle tracking system with real-time alerts**.
`README.md` is the official spec and is the source of truth — re-read the relevant section before
changing any endpoint. Evaluation is **strict on endpoint paths, HTTP methods, field names and
response shapes**.

- `backend/` — Go REST API + WebSocket alert hub, PostgreSQL + PostGIS
- `frontend/` — React (Vite) dashboard with Leaflet map, live alerts feed
- `docker-compose.yml` — postgis + backend (+ frontend) for local runs
- `SETUP.md` — required submission doc (setup, compose, curl examples, usage, architecture)

## Hard rules from the spec (do not break)

1. **Every JSON response includes `"time_ns": "<string>"`** — handler execution time in nanoseconds,
   measured with Go's `time` package from handler start to just before writing. Error responses too.
   Use `httpx.WriteJSON(w, status, start, payload)`; never hand-write responses.
2. **Do not rename / re-shape endpoints.** Required set:
   | Method | Path | Notes |
   |---|---|---|
   | POST | `/geofences` | validate polygon (see below) → `{id,name,status}` |
   | GET | `/geofences?category=` | `{geofences:[...]}` |
   | POST | `/vehicles` | `{id,vehicle_number,status}`; `vehicle_number` unique |
   | GET | `/vehicles` | `{vehicles:[...]}` |
   | POST | `/vehicles/location` | store, detect entry/exit, trigger alerts async → `{vehicle_id,location_updated,current_geofences:[{geofence_id,geofence_name,status:"inside"}]}` |
   | GET | `/vehicles/location/{vehicle_id}` | current location + `current_geofences:[{geofence_id,geofence_name,category}]` |
   | POST | `/alerts/configure` | `{geofence_id, vehicle_id?, event_type: entry\|exit\|both}` |
   | GET | `/alerts?geofence_id=&vehicle_id=` | `{alerts:[...]}` incl. geofence_name, vehicle_number |
   | GET | `/violations/history?vehicle_id=&geofence_id=&start_date=&end_date=&limit=` | limit default 50, max 500; `{violations, total_count}` |
   | WS | `/ws/alerts` | broadcast alert messages (format in README) |
   Extra endpoints are allowed (e.g. `DELETE /alerts/{alert_id}`, `GET /health`) but must not
   change the required ones.
3. **IDs are prefixed strings**: `geo_`, `veh_`, `alert_`, `viol_`, `evt_` (generated by DB sequences).
4. **Coordinates are `[latitude, longitude]`** in the API. PostGIS/GeoJSON use `(lng, lat)` —
   always swap at the DB boundary (`ST_MakePoint(lng, lat)`), never in handlers.
5. **Geofence validation**: category ∈ `delivery_zone|restricted_zone|toll_zone|customer_area`;
   ≥4 points; first == last (closed ring); lat ∈ [-90,90], lng ∈ [-180,180]; polygon must be
   valid (`ST_IsValid`, no self-intersection).
6. **Alert delivery is asynchronous** — `POST /vehicles/location` must not block on rule matching
   or WebSocket broadcast. All geofence events go to `violations`; alerts that match a rule are
   persisted in `alert_events` and broadcast.
7. Timestamps: ISO 8601 / RFC 3339 in and out, stored as `timestamptz`, returned in UTC.

## Architecture

```
backend/
  cmd/server/main.go          wiring: config → db pool → migrations → hub → dispatcher → router
  internal/config             env config (DATABASE_URL, PORT, CORS_ORIGINS, ...)
  internal/db                 pgx pool + embedded SQL migrations (run on startup)
  internal/httpx              WriteJSON/WriteError (adds time_ns), CORS, logging, recover, rate limit
  internal/geo                pure validation (polygon/lat/lng) — unit tested, no DB
  internal/store              SQL repositories (geofences, vehicles, locations, alerts, violations)
  internal/alerts             WebSocket hub (gorilla/websocket) + async Dispatcher worker
  internal/api                HTTP handlers + routes (Go 1.22 net/http pattern routing)
```

**Location update flow** (`POST /vehicles/location`), in one DB transaction:
1. `SELECT ... FOR UPDATE` the vehicle row (serialises concurrent updates per vehicle).
2. Insert into `vehicle_locations` (full history).
3. Point-in-polygon: `ST_Covers(boundary, point)` over GIST-indexed `geofences.boundary`.
4. If the timestamp is not older than the vehicle's last known timestamp: diff the result with
   `vehicle_geofence_state` → entry/exit events; update state + vehicle's last location;
   insert events into `violations`. Out-of-order (older) updates are stored as history only.
5. Commit, respond, then hand events to the `Dispatcher` (buffered channel + worker goroutines)
   which matches `alert_rules` (geofence match, vehicle null-or-match, event_type or `both`),
   inserts `alert_events`, and broadcasts via the hub.

Restricted zones: entries into `restricted_zone` geofences alert even without an explicit rule
when `ALERT_RESTRICTED_DEFAULT=true` (default).

## Commands

Go is **not installed on the host** — use Docker for Go tooling:

```bash
# from repo root
docker compose up --build                       # postgis + backend (:8080) + frontend (:5173)
docker compose up -d db                         # just the database

# Go tooling via container (mount backend/, cache modules in a named volume)
docker run --rm -v "$PWD/backend:/src" -v gomod:/go/pkg/mod -w /src golang:1.23 go mod tidy
docker run --rm -v "$PWD/backend:/src" -v gomod:/go/pkg/mod -w /src golang:1.23 go test ./...
docker run --rm -v "$PWD/backend:/src" -v gomod:/go/pkg/mod -w /src golang:1.23 go vet ./...

# frontend
cd frontend && npm install && npm run dev       # VITE_API_URL defaults to http://localhost:8080
cd frontend && npm run build && npm run lint   # lint = tsc --noEmit typecheck
```

On Git Bash for Windows prefix docker commands that mount `$PWD` with `MSYS_NO_PATHCONV=1`.

## Conventions

- Go: standard library first; deps are `pgx/v5`, `gorilla/websocket`, `golang.org/x/time/rate`.
  Handlers stay thin (parse → validate → store → respond); SQL lives in `internal/store`.
  Return typed errors from store (`store.ErrNotFound`, `store.ErrConflict`) and map to 404/409.
  Wrap errors with `%w`, log with `log/slog`. `context` from the request goes into every query.
- Validation errors → 400 with `{"error": "...", "details": [...], "time_ns": "..."}`.
- React: function components + hooks, API calls only through `src/api/` client, WebSocket via a
  single `useAlertsSocket` hook with auto-reconnect (exponential backoff). Every API action shows
  loading + success/error feedback (toasts).
- Keep code original — this is a graded individual assessment.
- Don't push to `origin` (it's the assessor's template repo); the user will set up their own
  private repo.
